# 业务趋势预测

本技能提供业务预测和目标制定的方法论，不直接负责取数或生成报告。执行中按需调用 `retrieving-context` 明确指标定义，调用 `querying-via-powerbi` 或 `querying-via-sql` 获取历史序列，调用 `visualizing-data` 生成预测图表，调用 `building-report` 承接报告交付。

## 核心原则

- 先确认预测问题，再选择模型。
- 先复现历史指标和口径，再做任何未来判断。
- 预测值不是目标值；目标还要考虑业务意愿、资源和风险。
- 简单、可解释、可回测的方法优先于复杂模型。
- 必须输出假设、区间、置信度和风险，不给伪精确结论。
- 近期存在结构性变化时，优先做场景预测，不机械延续旧趋势。

## 触发场景

当用户问题依赖未来值、趋势外推、目标设定或达成判断时使用本技能，例如：

- 下个月/下季度某指标预计是多少。
- 今年/月底/季度末目标能不能完成。
- 下个月目标定多少合适。
- 按当前趋势需要多少人力、预算、供给或库存。
- 指标接下来是否还会增长或下滑。
- 如果没有新增动作，未来一段时间大概会到多少。

如果用户问的是“为什么过去发生变化”，优先使用 `diagnosing-anomalies`。如果问题同时包含“为什么变”和“未来如何”，先排查异常和数据质量，再进入预测。

## 默认流程

### 1. 明确预测问题

确认以下信息。缺失但不影响大方向时先做合理假设并说明；缺失会改变结论时追问。

| 项目 | 要点 |
| --- | --- |
| 指标 | 名称、定义、分子分母、过滤条件、取数来源 |
| 预测窗口 | 未来几天、几周、几个月或几个季度 |
| 历史窗口 | 用多少历史期作为依据，是否覆盖可比季节 |
| 粒度 | 日、周、月、季度 |
| 范围 | 业务线、人群、渠道、区域、产品、版本等 |
| 用途 | 预测读数、目标制定、达成判断、资源预算、风险预警 |
| 交付 | 文字结论、表格、图表、报告或看板 |

如果预测结果用于目标制定，需要额外确认目标类型：保守目标、基准目标、挑战目标，或用于判断现有目标能否达成。

### 2. 获取可比历史序列

最小可用输入是一条包含 `date` 和 `value` 的时间序列。优先使用连续、无缺失周期的历史数据。预测窗口和历史窗口应使用相同指标口径、相同筛选条件和相同时间粒度。

较合适的例子：

- 最近 18 个月月度收入，用于预测未来 3 个月。
- 最近 90 天每日订单量，用于预测未来 14 天。
- 最近 52 周客服工单量，用于规划下月排班。

不适合直接预测的例子：

- 只有 3 个自然月数据，却要预测下一整年。
- 历史中途发生业务模式大改，但没有分段处理。
- 最新月尚未结束，却当作完整月份使用。

### 3. 检查历史序列

预测前必须检查：

- 最新周期是否完整，不能用半周期直接预测完整周期。
- 指标口径、数据采集、ETL、权限和过滤条件是否稳定。
- 是否存在缺失、重复、补数、截断、极端值。
- 是否有节假日、活动、投放、价格、供给、政策、版本发布等结构性影响。
- 历史窗口是否和预测窗口可比。

数据质量检查：

- 是否有缺失周期。
- 是否有重复日期。
- 是否存在非数值。
- 使用 log 趋势时，是否有 0 或负数。
- 是否存在数据延迟或补数。
- 指标口径是否变化。
- 是否有异常点或一次性事件。

业务可比性检查：

- 业务模式和价格机制是否一致。
- 活动和投放强度是否相近。
- 供给、库存、人力是否相近。
- 是否没有重大产品发布或政策变化。
- 日历是否可比，包括节假日和月份天数。

如果可比性较弱，使用场景预测，不要给单一且自信的点预测。

如果最新值本身疑似异常，先使用 `diagnosing-anomalies` 排查异常和数据质量，再做预测。

### 4. 建立预测基线

选择模型前先比较简单基线：

- 最新一期数值。
- 最近几期移动平均。
- 去年或上一季同周期。
- 近期增长率或当前 run rate。

业务运营场景中，简单基线往往已经足够有用，因为它透明、稳定、不容易过拟合。

### 5. 选择预测方法

先建立基线，再选择轻量模型：

| 场景 | 推荐方法 |
| --- | --- |
| 历史很短或波动很大 | naive、移动平均 |
| 水平稳定但有噪声 | 移动平均、指数平滑 |
| 趋势平稳上升或下降 | Holt 线性趋势、线性趋势回归 |
| 增长率比绝对增量更稳定 | log-linear 趋势 |
| 季节性主导且历史足够 | seasonal naive |
| 不确定选哪种 | `auto_baseline` 回测选择 |

详细模型选择读取 `references/model-selection.md`。

如果没有任何方法适合，不要硬给点预测，改为场景预测或说明无法可靠预测。

### 6. 回测和表达不确定性

历史数据足够时，必须用最近若干期做 holdout 回测，至少报告一种误差指标，如 MAE、MAPE 或 RMSE。预测结果要包含点预测、合理区间、关键假设、风险和置信度。

| 指标 | 含义 |
| --- | --- |
| MAE | 平均绝对误差，单位和原指标一致。 |
| MAPE | 平均百分比误差；真实值为 0 时避免使用。 |
| RMSE | 对大误差惩罚更重。 |

不要只因为某个模型误差略低就选择它。误差接近时，优先选择更稳定、更容易向业务方解释的方法。

预测区间是近似业务范围，不是严格统计置信区间。最终回答中应称为“合理区间”或“大致范围”。

置信度标签：

- 高：历史充足且可比，指标稳定，回测误差低，没有已知结构断点。
- 中：历史可用、误差可接受，但存在一定波动或业务上下文风险。
- 低：历史短、指标不稳定、数据缺失、存在重大结构断点，或未来强依赖未知动作。

常见失败模式：

- 用未完整的当前月预测完整月。
- 把活动驱动增长当成自然趋势。
- 因为近期趋势强而忽略季节性。
- 用过多小数位掩盖高不确定性。
- 分群结构正在变化，却只看总体预测。

### 7. 输出业务结论

推荐结构：

```text
预测结论：预计 <指标> 在 <预测窗口> 为 <预测值>，合理区间为 <下限>-<上限>。
依据：历史 <窗口> 呈现 <趋势/季节性/波动>，所选方法为 <模型>，回测误差约 <误差>。
目标建议：若用于目标制定，建议保守目标 <值>、基准目标 <值>、挑战目标 <值>。
关键假设：<口径稳定/无重大活动变化/数据完整>。
风险：<节假日/投放变化/供给约束/样本不足>。
置信度：<高/中/低>。
下一步：<需要补充的数据或业务动作>。
```

最终输出前完成自检：

- 指标名称、定义、预测窗口、时间粒度、历史窗口、范围和筛选条件是否清楚。
- 是否考虑最新周期完整性。
- 是否说明方法或模型名称，以及选择理由。
- 有条件时是否给出回测误差或波动证据。
- 是否隐藏了 CLI 或人工检查发现的 warning。
- 是否给出点预测、合理区间、置信度、关键假设、业务风险或结构断点。
- 目标类问题是否分开表达预测值和目标建议。
- 达成判断类问题是否给出所需 run rate 或目标缺口。
- 挑战目标是否说明所需业务抓手。
- 是否避免把预测说成保证发生。
- 是否避免不必要的小数精度。
- 低置信度预测是否明确标注。
- 下一步建议是否可执行。

### 8. 何时停止预测

出现以下情况时，停止给确定性预测，改为说明限制或做场景分析：

- 历史数据太短，无法支撑用户要求的预测窗口。
- 指标口径变化且无法统一。
- 最新周期不完整，且无法合理折算。
- 未来结果主要取决于未知业务动作。
- 已知结构性变化会让历史外推失真。

## 目标制定

当用户问“目标定多少”时，不要只给一个预测值。默认给三档：

- 保守目标：接近预测区间下沿，当前执行可较稳达成。
- 基准目标：接近点预测，代表正常经营预期。
- 挑战目标：高于基准，需要明确增长抓手或额外资源。

目标制定方法读取 `references/target-setting.md`。

## 内置脚本

当已经拿到结构化历史序列时，可用本地脚本做确定性轻量预测：

```bash
python predicting_trends/scripts/forecast.py <input.json>
```

输入输出契约读取 `references/input-contract.md`。

支持模型：

- `naive`
- `seasonal_naive`
- `moving_average`
- `weighted_moving_average`
- `exponential_smoothing`
- `holt_linear`
- `linear_trend`
- `log_linear_trend`
- `auto_baseline`

脚本只负责轻量预测、回测和 JSON 输出。业务口径、异常解释、结构性变化判断、目标取舍仍由 agent 完成。

## 与其他技能协作

- 需要指标定义、业务层级、表名、口径：调用 `retrieving-context`。
- 需要 Power BI 语义模型取数：调用 `querying-via-powerbi`。
- 需要 SQL 明细或聚合取数：调用 `querying-via-sql`。
- 发现近期异常、口径变化或结构断点：调用 `diagnosing-anomalies`。
- 需要精确预测图表：调用 `visualizing-data`。
- 需要沉淀成报告：调用 `building-report`。
