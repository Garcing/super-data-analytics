# 目标制定

目标是业务决策，不是纯预测。预测是在假设下估计“可能发生什么”；目标表达的是团队希望承诺或挑战什么。

## 默认三档目标

当用户问“目标定多少”时，默认给三档：

| 档位 | 含义 | 常见锚点 |
| --- | --- | --- |
| 保守目标 | 置信度较高，当前执行下较可达 | 预测区间下沿或近期 run rate |
| 基准目标 | 当前条件延续下的预期结果 | 点预测 |
| 挑战目标 | 需要增长抓手、额外资源或更强执行 | 预测区间上沿或计划增量 |

## 如何推荐

综合考虑：

- 可控性：团队能否在预测窗口内影响该指标。
- 提前量：距离周期结束是否还有足够时间改变结果。
- 波动性：预测区间是否足够窄，能支撑承诺。
- 业务意愿：管理层更看重确定性、适度挑战，还是激进增长。
- 资源计划：是否有明确抓手可以弥补缺口。

## 目标达成判断

针对“月底能不能完成目标”这类问题，计算：

- 当前实际值。
- 剩余目标缺口。
- 剩余周期数。
- 所需 run rate。
- 历史平均 run rate。
- 预测 run rate。
- 所需 run rate 与预测 run rate 的差距。

回答时给出明确状态：

- 大概率可达成。
- 有风险，但仍可追回。
- 若无额外抓手，较难达成。
- 数据不完整或目标口径不清，暂无法判断。

## 不要这样做

- 不要不解释风险就把目标直接设成预测值。
- 不要在没有业务抓手的情况下推荐挑战目标。
- 不要把低置信度预测包装成精确 KPI 承诺。
- 不要忽略产能、预算、供给或人力约束。
