# 模型选择

第一版刻意只使用可解释的轻量方法。选择模型时，优先选择能匹配指标形态和业务用途的最简单方法。

## 快速选择表

| 指标形态 | 优先选择 | 避免 |
| --- | --- | --- |
| 历史很短 | `naive`, `moving_average` | 假设很多的趋势模型 |
| 水平稳定但有噪声 | `moving_average`, `exponential_smoothing` | 强行外推趋势 |
| 最近周期最重要 | `weighted_moving_average`, `exponential_smoothing` | 过长历史均值 |
| 明确线性趋势 | `holt_linear`, `linear_trend` | 完全平稳的基线 |
| 增长率相对稳定 | `log_linear_trend` | 值为 0 或负数时使用 log 趋势 |
| 季节性主导 | `seasonal_naive` | 纯趋势模型 |
| 不确定选哪个基线 | `auto_baseline` | 不回测就手动挑模型 |

## 模型说明

### naive

重复最新一期观测值。适合历史很短、波动很大或难以建模的序列。很多运营指标里，它是一个很强的基线。

### moving_average

使用最近几期平均值。适合当前水平比久远历史更重要、且没有明显趋势的指标。变化快的指标用短窗口，稳定指标可用长窗口。

### weighted_moving_average

类似移动平均，但越近的数据权重越高。适合指标水平正在缓慢漂移，但直接用趋势模型又过于激进的情况。

### exponential_smoothing

围绕一个水平值平滑噪声。适合有随机波动但整体水平相对稳定的指标。它不显式建模趋势。

### holt_linear

同时建模水平和线性趋势。适合指标存在持续的加法型上升或下降。结构断点后、或趋势来自短期活动时要避免直接使用。

### linear_trend

拟合一条直线。解释简单，适合趋势外推；但当历史中存在阶跃变化、弯曲增长或明显饱和时风险较高。

### log_linear_trend

对数值拟合直线，含义是乘法型增长。只有当所有值都为正，且增长率比绝对增量更稳定时才使用。

### seasonal_naive

重复上一季节周期的同位置数值。适合季节性主导，并且至少有两个完整季节周期的情况。

## 何时升级到更复杂方法

出现以下情况时，应该使用第一版以外的更完整预测工具栈：

- 预测结果影响很大，值得投入更高建模成本。
- 存在多重季节性，例如周内周期和年末周期同时存在。
- 已知未来驱动变量，例如计划投放、价格、库存、人力、流量。
- 序列存在强自相关，且历史足够支持 ARIMA/SARIMA 这类方法。
- 问题需要因果解释，而不仅是趋势外推。
- 各业务分群差异很大，需要分层预测。

## 业务护栏

- 信任模型前先回测。
- 当误差差异很小时，优先选择稍微不那么准但更容易解释的方法。
- 不要把短期活动带来的增长外推成长期趋势。
- 当决策是分群决策时，不要把业务驱动完全不同的分群粗暴平均。
