# 图片报告（report → image）

把**数据分析的结论**直接渲染成**一张图片形式的分析报告**——含标题、KPI、图表、结论的一体化信息图 / 海报。它是报告的一种交付格式，与 HTML 报告**并列**（不是给 HTML 配封面图）。

> 一句话定位：分析做完了，数据和结论已经在手，要把它们「画」成一张可以直接看、可以下载、可以贴进 PPT / 飞书 / 微信的图。

## 架构概览

```
调用方 ──POST /images/generations + Bearer key──▶ apimart ──task_id──▶ 调用方
       （prompt 里带 数据JSON + 图表 + 结论 + 场景）         │
调用方 ──GET /tasks/{task_id}（轮询）─────────────────────┘
                       │ status=completed
                       ▼
            result.images[0].url[0]  ──fetch──▶ 下载到指定路径
```

- **异步**：提交返回 `task_id`，轮询 `/v1/tasks/{task_id}` 直到 `completed`，单张通常 ~30s。
- **取图**：`data.result.images[i].url` 是**数组**，取 `[0]`。
- **URL 时效**：约 24h 过期，脚本会下载到本地，**以本地文件为准**。

---

## 适用场景对比

| 维度 | 图片报告 | HTML 报告 |
|------|---------|----------|
| 形态 | 单张静态图（信息图 / 海报） | 在线交互页面 |
| 适合 | 一图传达完整结论、要下载/嵌 PPT/贴微信 | 多图、可钻取、长期在线分享 |
| 数据 | 一次性固化在图里，不可交互 | 可筛选、可联动 |
| 交付 | 本地文件 + 公网 URL | 公网链接 |

**选图片报告的场景：**
- 需要一张图就把「结论 + 关键数据 + 图表」全讲清楚（周报封面式信息图）
- 要嵌入 PPT / 飞书文档 / 微信 / 邮件，对方不打开链接
- 需要可下载、可打印的静态交付物
- 给高管/外部快速看，不要交互只要结论

**别用图片报告的场景：** 数据量很大、要交互筛选、要多张图钻取归因——这些走 HTML。

## 提示词写法

图片报告的质量**几乎完全取决于提示词**。模型不会自己脑补数据，必须把「数据 + 图表 + 结论 + 场景」全部喂进去。一个合格的提示词包含**六要素**：

### 1. 主题与场景

一句话说清：这是什么报告、给谁看、什么场合。决定信息密度和风格。

> 例：「这是一份**给运营周会**看的 GMV 周环比异动简报，受众是业务负责人，需要 10 秒内定位问题。」

### 2. 数据

把要呈现的真实数值原样喂进去：KPI、分项、时间序列。**不要让模型自己编数。**

> 例：
> ```json
> 核心指标：GMV 本周 1280 万，上周 1150 万，周环比 +11.3%
> 分渠道：
>   渠道A：520 万（+18%）  渠道B：430 万（+5%）  渠道C：330 万（+12%）
> 近 8 周 GMV 趋势：[820, 910, 980, 1020, 1100, 1080, 1150, 1280]
> ```

### 3. 要用的图表

逐张说明：**类型 + 表达什么 + 数据来源**。明确布局区块。

> 例：
> - 顶部：标题区 + 3 个 KPI 卡（GMV / 周环比 / 贡献最大渠道）
> - 中部：一张柱状图——各渠道 GMV 占比
> - 中下：一张折线图——近 8 周 GMV 趋势，高亮本周
> - 底部：2 条结论卡

### 4. 分析结论

2–4 条核心结论，标出重要性，指明哪些要在图上**高亮 / 加 callout**。

> 例：
> 1. 【高亮】GMV 周环比 +11.3%，主要由渠道 A（+18%）拉动
> 2. 渠道 B 增速放缓（+5%），需关注
> 3. 趋势连续 3 周上行

### 5. 版式与风格

配色、留白、字体感、是否带 logo / 品牌色。比例通过 `--size` 传，**不要在 prompt 里重复写比例**（避免上游理解冲突）。

> 例：「商务扁平风，主色 #2563EB 蓝 + 中性灰，大量留白，中文，数字用粗体突出。」

### 6.  强制规则

> **⚠️所有图表必须带数据标签**：每个柱子、折线节点、饼图扇区旁边都要**直接标出具体数值**。
>
> **理由**：当前大模型生成图片时，**无法保证数值与坐标轴刻度精确对齐**——柱子的高度、折线的位置、扇区的角度都可能有视觉偏差，读者凭坐标轴估读会被误导。**加数据标签把准确数值直接写在图上**，是规避这个问题的唯一可靠办法。
>
> 此外强制：
> - 所有数值必须与上面提供的数据**完全一致**，不得编造、不得随意四舍五入到失真
> - 不要画未在「要用的图表」里指定的图
> - 中文标签，单位明确（万 / %）

### 提示词模板（照填）

```
【主题】<一句话：什么报告、给谁、什么场合>
【数据】<真实数据：核心 KPI + 分项 + 时间序列，可直接贴 JSON>
【图表】<逐张：类型 + 表达什么 + 布局位置>
【结论】<2-4 条，标出要高亮的>
【风格】<配色 / 留白 / 字体感 / 品牌>
【强制规则】所有图表必须带数据标签（每个柱/点/扇区旁标出具体数值）；数值须与提供数据完全一致，不得编造；不画未指定的图。
```

### 完整示例（周报信息图）

把上面的内容拼成一个 prompt，用 CLI 生成：

```bash
node scripts/report.js image generate --prompt "生成一张数据分析报告信息图。
【主题】给运营周会看的 GMV 周环比异动简报，受众是业务负责人，10 秒内要能定位问题。
【数据】GMV 本周 1280 万、上周 1150 万、周环比 +11.3%；分渠道：渠道A 520万(+18%)、渠道B 430万(+5%)、渠道C 330万(+12%)；近8周GMV：820,910,980,1020,1100,1080,1150,1280。
【图表】顶部标题区+3个KPI卡(GMV/周环比/拉动渠道)；中部柱状图各渠道GMV占比；中下折线图近8周趋势并高亮本周；底部2条结论卡。
【结论】1.[高亮]周环比+11.3%，渠道A(+18%)主拉；2.渠道B增速放缓(+5%)需关注；3.趋势连续3周上行。
【风格】商务扁平，主色蓝#2563EB+中性灰，大量留白，中文，数字粗体。
【强制规则】所有图表必须带数据标签(每个柱/点/扇区旁标具体数值)；数值须与提供数据完全一致不得编造；不画未指定的图。" \
  --size 3:4 --resolution 2k \
  --output ./.super-data-analytics/results/gmv-weekly-20260630.png
```

> 选 `3:4` / `9:16` 适合竖版信息图；`16:9` 适合汇报封面。报告类建议 `--resolution 2k` 保证文字清晰。

## CLI命令

异步生图分三步，**任意一步可断点续跑**（每步幂等、可重复调用），从 building-reports/ 目录运行

```bash
# 一键到底（提交 → 轮询 → 下载），适合不会中断的场景
node scripts/report.js image generate [--prompt "<提示词>"|@file|-] --output <路径> [选项]

# 三步拆开（agent 中途断开后，从任一步接着跑）
node scripts/report.js image submit   [--prompt "<提示词>"|@file|-] [选项] [--dry-run] # 只提交，打印 task_id
node scripts/report.js image status   <task_id>                        # 轮询到终态，打印状态 + 图片 URL
node scripts/report.js image download <task_id> --output <路径>           # 下载图片
```

| 子命令 | 输入 | 输出（stdout） | 计费 |
|--------|------|------|------|
| `generate` | 提示词（`--prompt` 三态）+ `--output` + 生成选项 | `URL:` / `本地:` / `task_id` / `cost` | 是（`--dry-run` 时不计费） |
| `submit` | 提示词（`--prompt` 三态）+ 生成选项 | `{ task_id, cost? }` JSON | 是（`--dry-run` 时不计费） |
| `status` | `task_id` | `{ task_id, status, cost?, images?:[{url}], error? }` JSON | 否（只查询） |
| `download` | `task_id` + `--output` | `URL:` / `本地:` / `task_id` / `cost` | 否（只下载，图已生成） |

**提示词输入（三态，同 querying-data 的 `--sql` / `--payload`）**：

| 写法 | 含义 |
|------|------|
| `--prompt "<文本>"` | inline 提示词 |
| `--prompt @<file>` | 从文件读取提示词 |
| `--prompt -` | 从 stdin 读取提示词 |
| 不传 `--prompt` | 从 stdin 读取提示词 |

> 多行、含引号或含特殊符号的提示词建议写文件后用 `--prompt @<file>`。

**生成选项**（`submit` / 一键用，均有默认值）：

| 选项 | 默认 | 说明 |
|------|------|------|
| `--model` | `gpt-image-2` | `gpt-image-2`（平台中转，便宜）/ `gpt-image-2-official`（OpenAI 官方，画质最高） |
| `--size` | `1:1` | 比例（`16:9`/`9:16`/`3:4`/`4:3` …）、像素串（`3840x2160`）、或 `auto` |
| `--resolution` | `1k` | `1k`/`2k`/`4k`（**报告类建议 2k**，文字更清晰） |
| `--quality` | `auto` | auto/low/medium/high（**仅 official**） |
| `--format` | `png` | png/jpeg/webp（**仅 official**） |
| `--n` | `1` | 张数，official 允许 1–4，generation 仅 1 |
| `--dry-run` | — | 只打印请求体，不调用 API、不计费（仅 `submit` / 一键） |

**`--output <路径>`**（`download` / 一键必填）：
- `--output <路径>` → 落到指定路径（多张自动追加 `-<index>`）。
- 裸 `--output`（不跟值）→ 兜底 `~/Downloads/<时间戳>-<index>.<ext>`。
- 完全不传 → 报错（下载类命令必须显式 `--output`）。
- **agent 建议：**落在 `<工作区>/.super-data-analytics/results/<名字>.<ext>`，落盘根目录由 agent 决定

**两个模型的字段差异（关键）**

同一端点，靠 `model` 区分渠道，**支持字段不同**，脚本内部按白名单自动裁剪：

| 字段 | `gpt-image-2`（默认） | `gpt-image-2-official` |
|------|:---:|:---:|
| prompt / size / resolution | ✅ | ✅ |
| quality / format / background / moderation / mask | ❌ | ✅ |
| n | 仅 1 | 1–4 |
| image_urls（参考图，base64 也行） | ✅ | ✅（仅 URL） |
| official_fallback（失败升级官方） | ✅ | — |

> 选型：日常报告用默认 `gpt-image-2`（便宜，单张 ~0.006）已够；要最高画质、多张候选、或指定 jpeg/webp 时用 `--model gpt-image-2-official --quality high`。

## 配置（config.json）

凭证统一来自 `~/.super-data-analytics/config.json` 的 `env` 块（脚本不读 `.env`）：

| 变量 | 用途 |
|------|------|
| `APIMART_API_KEY` | apimart 中转接口密钥（必填） |
| `APIMART_BASE_URL` | 接口基址，默认 `https://api.apimart.ai/v1` |

配置缺失或字段不全时报错指引补全；由 agent 引导用户提供后写回 config.json 再重试。

### 依赖与代理

- **依赖**：Node 自带 `fetch`（Node 20+），无额外代理依赖；`scripts/` 下仅需 `npm ci` 装 `@vercel/blob`。
- **代理**：自动检测 `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`，为可选项——Node 24+ 原生支持 `NODE_USE_ENV_PROXY`，此时脚本 re-exec 自身注入该变量让 fetch 走代理；低版本 Node 不支持则放行，代理非必需。

## 生成后检查清单

图片报告生成后，**务必人工核对**（大模型生图不可完全信任）：

- [ ] 图表数值是否与提供的数据**完全一致**（最容易出错）
- [ ] 每个图表是否都**带了数据标签**
- [ ] 结论文字是否正确、无错别字
- [ ] 布局是否拥挤、文字是否可读（不够清晰就升 `--resolution 2k/4k` 或换 `--quality high`）

> 实测：默认 `gpt-image-2` + 1k 单张约 **30s**，cost ≈ **0.006**（1:1 @ 1k 实际出图 1254×1254）。`high + 2k/4k` 组合可达 130s。
