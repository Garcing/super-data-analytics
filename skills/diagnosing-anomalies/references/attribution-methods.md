# 归因方法速查（attribution-methods）

七种异动归因方法的选择指南。前三种（加法、乘法/LMDI、比率）由 `contribute` 工具直接支撑；后四种（漏斗链式、非线性替代、Shapley、监控根因）无专用工具，标注为「方法论指导手工/SQL 分析（配合 `sql_query`）」。

选择顺序：先看指标数学结构（加合/连乘/相除/复杂公式），再看场景（漏斗、多因素交互、告警排查）。

## 1. 加法分解（Delta 法）→ `contribute method="add"`

- **适用**：`Y = ΣXi` 或近似可加合的绝对量——收入、订单数、DAU、工单数按渠道/地区/品类等维度拆。最常用、最直观的默认选择。
- **数据要求**：`items` 分项**互斥且完整**（合起来正好等于总体）；每项两期数值 + 总体两期数值。
- **判据**：指标能写成"各部分之和"，且系数（价格、权重）本身没变。若价格/权重也在变，加法会漏项——换乘法或非线性替代。
- **解读**：`contribution_value` 为贡献量，`contribution_share`（Vi/ΔY）解释总变化分摊（可超 100%、可为负），`relative_contribution`（Vi/Y0）解释该分项让大盘较基准变了多少，二者不要混用。`checks.residual` 非 0 = 分项漏项/重复/不互斥。

## 2. 乘法/LMDI 分解 → `contribute method="multiply"`

- **适用**：`Y = ΠXi` 连乘结构——GMV=UV×CVR×AOV、PV=UV×人均PV。漏斗链路转成环节转化率连乘后也走此法（见第 4 节）。
- **数据要求**：`factors` 每个因子的 baseline/current **必须 >0**（内核强校验，log 拆解无法处理 0/负值）；总体由因子连乘自动得出，无需另传。
- **判据**：指标是因子乘积、且因子在业务上正交可分。因子含 0 或跨量级剧变时 log 结果不稳定，需业务认可的平滑或换方法。
- **解读**：LMDI 用对数平均权重 `L(Y1,Y0)·Δln(Xi)` 把贡献还原到原指标单位，各因子贡献加总≈ΔY（residual≈0）。`log_contribution_share` 是对数尺度占比；`contribution_value` 才是原单位贡献量，向业务汇报用后者。

## 3. 比率指标向后分解（组间组内）→ `contribute method="ratio"`

- **适用**：`Y = P/Q` 比率指标——转化率、支付成功率、投诉率、退款率，按分组（人群/渠道/地域）拆。
- **数据要求**：`groups` 每组四字段（分子分母×两期），分母必须>0；分组互斥且分母完整。
- **判据**：指标是比率且关心"各组自身变化 vs 结构变化"。**禁止**把比率指标当加法拆分子差值。
- **解读**：每行三分量——`within_contribution`（组内率值变化的贡献）、`mix_contribution`（分母占比即结构变化的贡献，负值常表示低于大盘的组占比上升）、`interaction_contribution`（交叉项）。各组率值都变好但总体变差（辛普森悖论）时，答案在 mix 项——优先解释结构变化。

## 4. 漏斗链式拆解 —— 方法论指导手工/SQL 分析（配合 `sql_query`）

- **适用**：注册、下单、支付等多阶段链路异动，目标是先定位断点环节。
- **数据要求**：各节点两期去重人数（`sql_query` 按节点口径取数），换算成各环节转化率。
- **做法**：把整体转化率拆成环节转化率连乘后，**环节转化率作为 factors 调 `contribute method="multiply"`**——计算有工具支撑，"链路定义 + 去重口径"由 agent 用 SQL 准备。找到贡献最大环节后按端/渠道/版本/人群递归下钻。
- **判据**：异动发生在链路型业务过程、且能明确画出节点序列。

## 5. 非线性替代（泰勒一阶 / 定基替代）—— 方法论指导手工/SQL 分析（配合 `sql_query`）

- **适用**：`Y = f(X1..Xn)` 复杂公式——ROI、综合评分、带约束收益，不属于前三类结构。
- **数据要求**：明确的指标公式 `f()` + 各因子两期值（先 `retrieve_search` 确认公式口径）。
- **做法**：一阶泰勒 `Vi = ∂f/∂Xi|基点 · ΔXi`（因子变化不大时）；或定基替代——固定其余因子为基线值、只替换因子 i 求差（直观但受替换顺序影响，有交互残差）。残差单列或按贡献权重分摊。
- **判据**：因子变化剧烈时一阶泰勒不可靠；定基顺序敏感大时应考虑 Shapley。

## 6. Shapley 值分摊 —— 方法论指导手工/SQL 分析（配合 `sql_query`）

- **适用**：多因素同时作用且存在交互——多个运营活动/优惠策略共同影响 GMV，差值分解无法公平分摊交互项。
- **数据要求**：价值函数 `v(S)`——每个因素**子集**生效时的指标值，通常来自正交实验、AB 实验或可靠业务规则（可由 `sql_query` 按切片取数估算）。没有可靠 `v(S)` 时不要强行做 Shapley，退回贡献度拆解或建议实验设计。
- **做法**：φi = 因素 i 在所有加入顺序下边际增量的加权平均；组合数随因素数爆炸，因素 ≤4 为宜。成本可得时补 ROI = φi/成本。
- **判据**：需要公平分摊交互、且能拿到（或近似构造）子集取数。

## 7. 监控场景根因排查（Adtributor 思路）—— 方法论指导手工/SQL 分析（配合 `sql_query`）

- **适用**：告警触发后在大量维度/维值中快速筛根因候选——定位"真实值相对期望值的差异集中在哪里"。
- **数据要求**：每个维度值的真实值 Ai 与期望值 Fi（预测基线/上期，`sql_query` 准备），及总体 A/F。
- **做法**：先确认 A−F 异动成立；按维度算解释力 `EPi = (Ai−Fi)/(A−F)`，配合真实/期望分布差异（如 JS 散度）；对 Top 维度值交叉下钻（控制层数与样本量）；最后用业务事件/发布记录验证。Adtributor 偏单维定位，强交互多根因需交叉下钻。
- **判据**：告警驱动、维度多、需要快速收敛候选清单的场景。EP 高只说明解释力强，不等于因果。

## 与 contribute 的对应速查

| 方法 | 工具支撑 | method |
|---|---|---|
| 加法分解 | `contribute` | `add` |
| 乘法/LMDI | `contribute` | `multiply` |
| 比率组间组内 | `contribute` | `ratio` |
| 漏斗链式 | 计算复用 `contribute`（factors=环节转化率） | `multiply` |
| 非线性替代 | 无，手工/SQL | — |
| Shapley | 无，手工/SQL | — |
| 监控根因 | 无，手工/SQL | — |
