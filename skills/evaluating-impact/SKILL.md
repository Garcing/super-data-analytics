# 效果评估与实验检验

回答“做的事情有没有用、效果多大、值不值、接下来怎么做”。先确认评估对象和决策，再选最轻量且可信的方法。

## 核心原则

- 先复现动作、分流/曝光、指标、归因窗口和成本口径。
- 有健康随机对照时才支持强因果；无随机对照不包装成强因果。
- 主指标、护栏指标、效果量和业务收益一起看。
- 不显著不等于没效果；统计显著不等于值得上线。
- ROI 必须区分总收入、因果增量、毛利和净收益。

## 默认流程

### 1. 定义评估问题

确认：

- 动作与开始/结束时间、观察窗口、归因窗口。
- 实验组/对照组、触达/曝光/实际处理人群。
- 事先定义的主指标、护栏指标、诊断指标。
- 最小可接受效果或目标值。
- 补贴、投放、库存、履约、人力、机会成本与退款。
- 要支持的决策：全量、停止、扩样本、加码或分层推进。

缺失会改变方法或结论时追问。指标先用 retrieving-context 对齐，数据由 `sql_query` 获取。

### 2. 复现口径与环境

检查指标分子分母、去重粒度、分流与曝光定义、窗口完整性、数据延迟/补数，以及同期活动、节假日、投放、价格、库存、事故或数据链路变化。

成本与收益必须同一观察口径；收入、毛利、贡献毛利、净利润不能混用。

### 3. 按证据条件选方法

| 条件 | 方法 | 结论强度 |
|---|---|---|
| 随机实验组/对照组 | `ab_rate` 或 `ab_mean` | 设计健康时可支持强因果 |
| 非随机但有处理/对照与干预前后 | `did` | 较可信，但依赖平行趋势等假设 |
| 只有处理/对照的干预后数据 | 可比组差异 | 方向性或弱因果支持 |
| 只有处理组前后 | 前后/同环比/漏斗 | 仅方向性 |
| 只有收益与成本 | `roi` | 投入产出判断，不证明因果 |
| 样本、处理或口径不清 | 停止强结论 | 无法判断 |

具体设计与方法边界见 [experiment-design.md](references/experiment-design.md)。

### 4. A/B 前置检查

在调用显著性计算前确认：

- 随机分流单位和指标统计单位一致。
- 实际样本比例符合设计比例；SRM 异常时实验结论作废。
- 主指标在实验前定义，避免事后挑指标和多重比较。
- 观察窗口覆盖完整业务周期，没有盯盘显著就提前停止。
- 跨组污染、重复曝光和触达失败已处理。
- 样本量足以检测预设 MDE；实验前可用 `sample_size_rate` 估每组样本。

`impact` 不自动做 SRM、随机性、污染或提前停止检查，这些必须单独完成。

### 5. 调用 impact

`analysis_type` 取：`ab_rate`、`ab_mean`、`did`、`roi`、`sample_size_rate`。payload 字段直接放在 `payload` 内，按工具输入 schema 传，不再嵌套 `params`。

解读要点：

- `ab_rate`：同时报告两组率值、绝对/相对 lift、p 值和绝对 lift 的置信区间。对照基率为 0 时相对 lift 无定义。
- `ab_mean`：同时看均值差、置信区间和 Cohen's d；小样本、重尾或强偏态时正态近似不足。
- `did`：报告两组各自变化和双重差分；工具只算四格，不验证平行趋势。
- `roi`：说明 benefit 的增量属性；高补贴/退款/低毛利场景优先毛利或增量毛利 ROI。
- `sample_size_rate`：输出是每组近似样本量，实际还要考虑触达率、分流比例和完整周期。

### 6. 护栏与异质性

主指标改善后继续检查留存、投诉、退款、卸载、性能、收入质量等护栏。按预先合理的人群/渠道/地区/版本看异质性，但不要事后无限切片找“显著人群”。

评估窗口存在异常波动时，先用 diagnosing-anomalies 判断是否由数据或外部事件干扰。

### 7. 做决策

- 显著、效果量达到业务门槛、CI 下界可接受、护栏稳定 → 可全量/继续。
- 不显著且样本不足或 MDE 过大 → 继续实验或扩样本，不能说“无效”。
- 显著但效果太小、成本过高或护栏恶化 → 不建议全量。
- DID 平行趋势不成立 → 降级为方向性，补更合适对照或实验。
- 增量毛利 ROI >0 且护栏稳定 → 可续投；扩量时考虑边际递减。
- 只有前后对比 → 明确“观察相关”，不写“动作导致”。

## 关键方法边界

### A/B

- p 值不是“效果为真的概率”。
- CI 不含 0 只说明统计证据；还要看下界是否超过业务最小可接受效果。
- 多指标/多切片增加假阳性；主指标优先，其他作为护栏或探索。
- `ab_mean` 聚合口径必须一致（都按用户或都按订单）。

### DID

- 干预前应有多期数据验证处理/对照趋势大致平行。
- 只有一个前置周期无法检验趋势，结论强度降级。
- 只影响一组的同期活动、用户迁移、提前泄露或滞后生效都会污染估计。
- 分批干预、动态效应或面板回归超出轻量工具能力，需专项分析。

### ROI

- `roi=(benefit-cost)/cost`，但公式正确不等于 benefit 有因果增量含义。
- 增量收益优先来自 A/B/DID lift × 可影响规模。
- 成本包括补贴、投放、履约、库存、人力和机会成本；收益扣退款与蚕食。
- 短期 ROI 为正但长期护栏恶化时不加码。

## 输出模板

```text
评估结论：<动作> 对 <主指标> 的观察效果为 <幅度>。
方法与证据：<A/B/DID/前后/ROI>；<样本、效果量、CI/p 值或 DID/ROI>。
设计检查：<SRM、随机性、平行趋势、窗口、同期干扰>。
业务判断：<护栏、增量收益、成本与 ROI>。
结论强度：<强因果/较可信但依赖假设/仅方向性/无法判断>。
建议：<全量/继续观察/扩样本/停止/分层推进>及触发条件。
限制：<未验证项与最低补充数据>。
```

必须给效果大小，不只说显著/不显著。需要正式发布时先用 validating-analyses 复核设计与数字，再交给 building-reports。

## 停止条件

- 处理定义、分流或指标口径不清。
- SRM、污染或数据质量问题使实验失效。
- DID 无法获得可比对照或干预前趋势。
- 归因窗口尚未结束或数据未稳定。
- 收益/成本口径无法对齐。

此时输出“无法判断 + 缺什么 + 如何补”，不要给强结论。
