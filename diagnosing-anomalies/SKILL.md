# 指标异动归因

本技能提供异动归因的方法论，不直接负责取数或生成报告。执行中按需调用 `retrieving-context` 明确指标定义，调用 `querying-data --source powerbi` 或 `querying-data --source sql` 获取数据，调用 `visualizing-data` 生成精确图表，调用 `building-reports` 承接报告交付。

## 运行环境与依赖

- Python `>=3.10`；脚本和测试只使用标准库。
- `requirements.txt` 以注释明确“无第三方依赖”，无需安装额外包。
- 本技能不读取 `config.json` 或环境变量；取数凭证由 `querying-data` 管理。


## 核心原则

- 先判断“是否真的异常”，再解释“为什么异常”。
- 先复现指标和口径，再做任何归因判断。
- 把数据问题、统计波动、业务变化、外部事件分开验证。
- 贡献度说明的是“能解释多少变化”，不自动等于因果。
- 优先选择业务可行动、可验证、口径互斥的拆解维度。
- 结论必须标注置信度：已验证、较可能、待验证、已排除。

## 默认流程

### 1. 明确诊断问题

确认以下信息，缺失但不影响大方向时先做合理假设并说明；缺失会改变结论时追问。

| 项目 | 要点 |
| --- | --- |
| 指标 | 名称、业务定义、分子分母、过滤条件、粒度 |
| 异动 | 当前窗口、基准窗口、变化方向、变化幅度 |
| 范围 | 业务线、人群、渠道、区域、产品、版本等 |
| 目标 | 定位根因、解释波动、排除数据问题、给出行动建议 |
| 交付 | 文字结论、表格、图表、报告或看板 |

### 2. 验证异动成立

不要直接接受“异常”描述。先检查：

- 当前值、基准值、绝对变化、相对变化。
- 当前窗口和基准窗口是否同口径、同粒度、同完整度。
- 是否超出历史正常波动区间，如同环比、移动均值、标准差、IQR、预测基线。
- 是否存在周期性、节假日、活动日、发布、补数或数据延迟。
- 异动形态是什么：单点尖峰/尖谷、阶跃变化、持续漂移、周期性反复、分段恢复。

### 3. 排除口径和数据质量问题

解释业务原因前，先检查会改变结论的数据问题：

- 指标口径是否近期变更，分子分母是否同源。
- 数据是否延迟、补数、重复、缺失、截断。
- join 是否放大或丢失样本，维表是否更新。
- 近期埋点、ETL、看板、权限、过滤条件是否变化。
- 当前窗口是否尚未完整，不要用未完整周期和完整周期硬比。

若发现数据问题，先把它作为候选原因量化，不能把脏数据下钻结果当成业务根因。

### 4. 选择拆解路径和诊断模式

按指标结构选择方法，而不是固定套一个公式：

| 指标类型 | 推荐拆解 |
| --- | --- |
| 加法型绝对量，如收入、订单数、DAU | 读取 [`references/additive-delta.md`](references/additive-delta.md)，用 Delta 法计算维度差值贡献和帕累托排序 |
| 乘法链路，如 GMV=流量*转化*客单价 | 读取 [`references/multiplicative-lmdi.md`](references/multiplicative-lmdi.md)，用 LMDI/log 拆解因子贡献 |
| 比率型，如转化率、成功率、投诉率 | 读取 [`references/ratio-bwd.md`](references/ratio-bwd.md)，用组间组内拆解区分表现变化和结构变化 |
| 漏斗/链路指标 | 读取 [`references/funnel-chain.md`](references/funnel-chain.md)，逐节点定位流量、转化、人均频次等关键断点 |
| 多因素共同作用 | 读取 [`references/shapley.md`](references/shapley.md)，用 Shapley 思路分摊交互贡献 |
| 监控告警或多维组合 | 读取 [`references/monitoring-root-cause.md`](references/monitoring-root-cause.md)，对比真实值与期望值，定位解释力和分布变化明显的维度 |
| 非线性指标或复杂公式 | 读取 [`references/nonlinear-substitution.md`](references/nonlinear-substitution.md)，用泰勒展开或定基替代近似归因 |

若对应方法卡提供脚本调用方式，拿到结构化聚合数据后优先使用 `scripts/contribution.py` 计算贡献度，避免手算公式出错。

同时按业务场景选择下钻方向：

- **漏斗断点**：复现各节点流量和转化率，找变化贡献最大的节点，再按端、渠道、版本、人群下钻。
- **流量结构变化**：拆开“渠道量变少”和“渠道质量变差”，结合投放预算、素材、竞价、活动节奏验证。
- **用户/客户结构变化**：比较分组占比和组内指标变化，重点识别辛普森悖论。
- **供给或库存约束**：同时看需求侧和供给侧，检查库存、排期、价格、履约能力。
- **系统或数据链路问题**：对比服务端和客户端、明细表和汇总表、看板和源表，建立发布时间线。
- **外部事件或策略影响**：先量化受影响切片，再用天气、政策、竞品、活动、实验或风控规则解释；不要只凭时间吻合判因果。

### 5. 分解和验证驱动因素

按“先广后深”推进：

1. 先做一级维度贡献排序，找出能解释大部分变化的维度。
2. 对 Top 维度继续交叉下钻，但每一层都要保留总体变化的可解释比例。
3. 对比 numerator、denominator、mix、within-segment movement，不要只看单个率值。
4. 检查是否存在辛普森悖论：分组趋势和总体趋势相反时，必须解释结构变化。
5. 把候选原因和业务事件、发布记录、投放变化、运营动作、外部环境互相印证。

### 6. 输出归因结论

输出必须包含：

- 指标名称、口径、当前窗口、基准窗口。
- 当前值、基准值、绝对变化、相对变化，以及异动是否成立。
- 数据质量和口径检查结论。
- Top 驱动因素、贡献量 `Vi`、贡献率 `Ci = Vi / ΔY`、相对贡献 `Ri = Vi / Y0` 或影响规模。
- 已验证证据、未解释残差、置信度和下一步建议。

推荐结构：

```text
结论：<指标> 在 <当前窗口> 相比 <基准窗口> <上升/下降> <幅度>，主要由 <驱动因素> 解释。
证据：<贡献度/影响量/维度明细/时间吻合/数据质量检查结果>。
判断：<已验证/较可能/待验证>，原因是 <证据强弱>。
影响：<业务含义或风险>。
建议：<下一步验证或动作>。
未解释：<剩余变化、缺失数据、口径限制>。
```

表达边界：

- 不要把相关性写成因果。
- 不要把“贡献最大”写成“根本原因”，除非有独立证据验证。
- 不要混淆贡献率和相对贡献：贡献率解释总变化分摊，相对贡献解释分项让大盘较基准变化多少。
- 不要只报告百分比，必须给出基数或影响量。
- 数值图表使用 `visualizing-data`，不要用 AI 生图。

## 何时停止下钻

- Top 驱动已解释大部分变化，继续下钻只增加噪音。
- 更深维度样本量太小，不足以支撑结论。
- 维度不是业务可行动因素，也无法验证。
- 数据源无法支持更细粒度，继续分析会制造伪精确。

## 与其他技能协作

- 需要指标定义、业务层级、表名、口径：调用 `retrieving-context`。
- 需要 Power BI 语义模型取数：调用 `querying-data --source powerbi`。
- 需要 SQL 明细或聚合取数：调用 `querying-data --source sql`。
- 需要精确图表：调用 `visualizing-data`。
- 需要沉淀成报告：调用 `building-reports`。

## 内置脚本

```bash
python diagnosing-anomalies/scripts/contribution.py add <input.json>
python diagnosing-anomalies/scripts/contribution.py multiply <input.json>
python diagnosing-anomalies/scripts/contribution.py ratio <input.json>
```

脚本只负责贡献度计算和加总校验。业务口径选择、维度选择、数据质量判断、因果验证仍由 agent 完成。
