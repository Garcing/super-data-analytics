# 指标异动归因

本技能提供异动归因的方法论，不直接负责取数或生成报告。执行中按需调用 `retrieving-context` 明确指标定义，调用 `querying-via-powerbi` 或 `querying-via-sql` 获取数据，调用 `visualizing-data` 生成精确图表，调用 `building-report` 承接报告交付。

## 核心原则

- 先判断“是否真的异常”，再解释“为什么异常”。
- 先复现指标和口径，再做任何归因判断。
- 把数据问题、统计波动、业务变化、外部事件分开验证。
- 贡献度说明的是“能解释多少变化”，不自动等于因果。
- 优先选择业务可行动、可验证、口径互斥的拆解维度。
- 结论必须标注置信度：已验证、较可能、待验证、已排除。

## 默认流程

### 1. 明确诊断问题

确认以下信息，缺失但不影响大方向时先做合理假设并说明；缺失会改变结论时追问。

| 项目 | 要点 |
| --- | --- |
| 指标 | 名称、业务定义、分子分母、过滤条件、粒度 |
| 异动 | 当前窗口、基准窗口、变化方向、变化幅度 |
| 范围 | 业务线、人群、渠道、区域、产品、版本等 |
| 目标 | 定位根因、解释波动、排除数据问题、给出行动建议 |
| 交付 | 文字结论、表格、图表、报告或看板 |

### 2. 验证异动成立

不要直接接受“异常”描述。先检查：

- 当前值、基准值、绝对变化、相对变化。
- 是否超出历史正常波动区间，如同环比、移动均值、标准差、IQR、预测基线。
- 是否有周期性、节假日、活动日、工作日效应。
- 异动是单点、阶跃、持续、周期性反复，还是缓慢漂移。

如需要更完整的判断框架，读取 `references/anomaly-workflow.md`。

### 3. 排除口径和数据质量问题

解释业务原因前，先检查会改变结论的数据问题：

- 指标口径是否近期变更，分子分母是否同源。
- 数据是否延迟、补数、重复、缺失、截断。
- join 是否放大或丢失样本，维表是否更新。
- 近期埋点、ETL、看板、权限、过滤条件是否变化。
- 当前窗口是否尚未完整，不要用未完整周期和完整周期硬比。

若发现数据问题，先把它作为候选原因量化，不能把脏数据下钻结果当成业务根因。

### 4. 选择拆解路径

按指标结构选择方法，而不是固定套一个公式：

| 指标类型 | 推荐拆解 |
| --- | --- |
| 加法型绝对量，如收入、订单数、DAU | 维度差值贡献、帕累托排序 |
| 乘法链路，如 GMV=流量*转化*客单价 | 因子拆解、log 拆解或 Shapley 思路 |
| 比率型，如转化率、成功率、投诉率 | 分子分母拆开，区分组内表现和结构变化 |
| 漏斗/链路指标 | 逐节点复现，定位流量、转化、人均频次等关键节点 |
| 多维组合 | 先业务维度排序，再交叉下钻，控制搜索空间 |
| 监控告警 | 对比真实值与期望值，找贡献最大且分布变化明显的维度 |

细节读取 `references/contribution-methods.md`。

若已经拿到结构化聚合数据，优先使用 `scripts/contribution.py` 计算贡献度，避免手算公式出错。输入输出规范读取 `references/contribution-calculator.md`。

### 5. 分解和验证驱动因素

按“先广后深”推进：

1. 先做一级维度贡献排序，找出能解释大部分变化的维度。
2. 对 Top 维度继续交叉下钻，但每一层都要保留总体变化的可解释比例。
3. 对比 numerator、denominator、mix、within-segment movement，不要只看单个率值。
4. 检查是否存在辛普森悖论：分组趋势和总体趋势相反时，必须解释结构变化。
5. 把候选原因和业务事件、发布记录、投放变化、运营动作、外部环境互相印证。

常见诊断模式读取 `references/diagnostic-patterns.md`。

### 6. 输出归因结论

推荐结构：

```text
结论：<指标> 在 <当前窗口> 相比 <基准窗口> <上升/下降> <幅度>，主要由 <驱动因素> 解释。
证据：<贡献度/影响量/维度明细/时间吻合/数据质量检查结果>。
判断：<已验证/较可能/待验证>，原因是 <证据强弱>。
影响：<业务含义或风险>。
建议：<下一步验证或动作>。
未解释：<剩余变化、缺失数据、口径限制>。
```

最终输出前读取 `references/output-checklist.md` 做自检。

## 何时停止下钻

- Top 驱动已解释大部分变化，继续下钻只增加噪音。
- 更深维度样本量太小，不足以支撑结论。
- 维度不是业务可行动因素，也无法验证。
- 数据源无法支持更细粒度，继续分析会制造伪精确。

## 与其他技能协作

- 需要指标定义、业务层级、表名、口径：调用 `retrieving-context`。
- 需要 Power BI 语义模型取数：调用 `querying-via-powerbi`。
- 需要 SQL 明细或聚合取数：调用 `querying-via-sql`。
- 需要精确图表：调用 `visualizing-data`。
- 需要沉淀成报告：调用 `building-report`。

## 内置脚本

```bash
python diagnosing-anomaly/scripts/contribution.py add <input.json>
python diagnosing-anomaly/scripts/contribution.py multiply <input.json>
python diagnosing-anomaly/scripts/contribution.py ratio <input.json>
```

脚本只负责贡献度计算和加总校验。业务口径选择、维度选择、数据质量判断、因果验证仍由 agent 完成。
