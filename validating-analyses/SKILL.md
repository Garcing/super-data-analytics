# 分析成品质检

本技能是对「已经做出来的分析」做独立质检，不是从头做分析。它回答一个问题：**这份分析能不能拿去给决策方看？** 重点抓产出方自己不容易发现的系统性错误——答非所问、口径漂移、计算不可复算、常见统计陷阱、图表误导——而不是重新跑一遍归因或评估。

定位是**最终成品兜底关**，横向适用于任何来源的分析：自己刚产出的、同事交接的、看板截图、SQL 结果、报告草稿、第三方给出的结论。

执行中按需调用 `retrieving-context` 校验指标口径，调用 `querying-data sql` 或 `querying-data powerbi` 复算关键数字，调用 `visualizing-data` 重画图核对，调用 `building-reports` 落地修订后的报告。各分析域的内部检查不在这里复刻：异动归因查 `diagnosing-anomalies`，效果评估查 `evaluating-impact`，趋势预测查 `predicting_trends`。

## 运行环境与依赖

本技能是纯方法论质检，无脚本、无第三方 Node/Python 依赖，也不直接读取环境变量。复算、重画或重新发布时，使用对应技能的运行环境与凭证。


## 核心原则

- 验证的是分析**实际做出的主张**，不是它看起来精不精致。
- 优先拿实证：能复算就复算，能追溯到源数据就追溯，不能验证的就明确标注“未验证”。
- 按**对决策的影响**排优先级，不机械跑所有检查。修辞性小瑕疵不阻断分享，但数字、分母、口径、对比基准、结论可靠性的硬伤必须阻断。
- 区分“已验证事实”“推断”“ caveats”“待办 blocker”，不要混在一起。
- 高风险对象加倍审查：意外结果、对外汇报结论、因果表述、高影响决策、外部公开分享。

## 触发场景

当一份分析即将交付或已被质疑可信度时使用，例如：

- “帮我看看这份报告有没有问题，下午要给老板看。”
- “这个数字靠谱吗？怎么比看板上高这么多。”
- “上线前帮我复核一下结论。”
- “同事给的分析，我帮他验收一下。”
- “这张图会不会有误导？”
- 分析结论意外、过于完美、或与既有认知冲突。

如果用户只是要“从头做一次分析”，走 `aligning-requirements` 编排；本技能只接“已经有的成品”。

## 默认流程

### 1. 清点成品与主张

识别被验收的对象：报告、SQL、notebook、看板、图表、粘贴的分析文字、推荐结论。提取它的：要回答的问题、受众与决策、核心主张、头条数字、数据来源、时间窗口、人群、过滤条件、对比基准、已声明的 caveat。**逐条确认用户关心的每个指标都真的出现在分析里**，或被明确标注为不可得/不适用，不能静默缺失。

### 2. 校验问题、口径与假设

- 分析回答的是**那个业务问题本身**，还是一个“附近更简单的问题”。
- 人群、过滤、排除规则、采样、指标定义、公式、单位、分母、时区、cohort、对比期、基准是否和决策需要一致。
- 标出隐藏排除、口径前后不一致、不完整周期对比、以及缺乏实验或可信因果证据却用了因果措辞的表述。

口径不清先调 `retrieving-context` 对齐权威定义，不要在错误口径上继续验。

### 3. 校验数据来源与质量风险

确认选用的表、文件、看板、导出对当前决策合适且足够新：as-of 日期、分区覆盖、行/类别完整性、空值处理、去重、过滤逻辑、join 覆盖、来源错配。任何可能**改变结论**的质量风险都要查。需要源数据或元数据时走 `querying-data` 做抽样、schema、行数核对。

### 4. 复算关键数字

对影响最大的数字独立复算：粒度、小计、分母（且分母非零）、率值基数、环比/同比基数、加权平均（注意分组大小）、单位/币种/时区、互斥分类是否加总等于总计。SQL 重点看 join 类型、group by 粒度、过滤、distinct 计数、以及 join 前后的行数。

### 5. 合理性与分析陷阱排查

把量级与已知看板、历史报告、财务口径、产品量级对比。重点追问：趋势突变/平坦、整 round number、0% 或 100% 的率、应加总到约 100% 的分项占比、**过于丝滑地印证假设没有摩擦**的结果、空人群/新实体/边界日期的边界行为。常见陷阱见下节。

### 6. 图表诚实性

确认图表类型、坐标轴、刻度、区间、标题、标签、单位、排序、注释、颜色、精度是否如实表达数据：柱状图是否从 0 起、对比图刻度是否一致、截断轴/双轴/3D/不等距区间是否有必要且说明、标题是否夸大于数据所支持的结论、caveat 是否贴在它限定的结论旁边。渲染类成品（报告/看板/幻灯片/PDF/HTML）要检查**最终渲染态**：图是否坏了、表是否缺、文字是否被裁、是否有过期占位。

### 7. 评结论与推荐

每条结论是否有可见证据或留痕支撑；把“已验证发现”和“推断/caveat/开放问题”分开；找出超出证据的推荐、未被设计支撑的因果表述、被忽略的替代解释。

### 8. 出置信度评级与必改项

按对决策的影响排序问题。区分 **blocker**（硬伤，必须改才能发）和 **caveat**（可带说明发布）。blocker 包括：数字/分母/join/时间窗/人群/对比基准/结论不可靠、缺少必需访问、检查未跑、渲染步骤坏了、口径风险未解决、缺少负责人确认。复算用过的 SQL / notebook / 表路径要留可追溯链接。

## 常见分析陷阱

- **Join 爆炸**：多对多 join 静默放大行数，吹高 count/sum。对比 join 前后的行数和 distinct 主实体；右表多行时先聚合到目标粒度再 join；计数实体用 `COUNT(DISTINCT primary_id)`；故意一对多 join 要注释。
- **幸存者偏差**：只包含今天还在的实体，漏掉已删除/流失/失败的。追问“谁不在这个数据集里”，以及缺失人群是否改变结论。
- **不完整周期对比**：未完整周期对比完整周期。用完整周期、对比同样多的已过天数，或显著标注 partial-period。
- **分母漂移**：eligible 人群在期/段之间变化。确认转化/流失/激活/留存率在对比组间定义稳定。
- **平均的平均**：把预聚合的平均值直接再平均，未按组大小加权。从原始分子分母聚合，或用加权平均。
- **时区错配**：来源时间戳约定或日截断不同。确认已标准化，或显式声明时区与截断点。
- **分段选择偏差**：用被测量的结果来定义分段（如“高活跃用户留存更好”）。做 lift/因果/行为差异时按干预前特征定义对比组。
- **其他**：辛普森悖论（总体与分组趋势相反）、相关性当因果、小样本、离群点主导均值（需中位数或分布）、多重检验、挑时间段、look-ahead 偏差。

分析域特有的陷阱不在本节展开：异动归因的 mix/within、口径变更查 `diagnosing-anomalies`；实验的 SRM/样本量/选择偏差查 `evaluating-impact`；预测的 partial-period/结构断点查 `predicting_trends`。

## 复核 recipe

- 从原始分子分母重算一个关键指标。
- 抽几条记录，跟过 join/过滤/最终输出。
- 把一个关键总量与可信看板、历史报告、财务口径对账。
- 从组件反推头条数字（如 用户数 × 人均收入）。
- 跑一个“单日/单段/单实体”边界检查，验证过滤与 join 行为。
- 结论意外或高风险时，换一条查询路径重算同一指标。

## 置信度评级

- `可发布`：方法成立、关键计算已验证或低风险、caveat 清楚、剩余问题都是次要修饰级。
- `带说明发布`：方向可用，但特定假设、限制或未验证项必须明确告知决策方。
- `需修订`：存在实质性错误、无据结论、缺失检查或方法问题，发布前必须改。

## 输出模板

除非用户要更轻的复查，按此结构输出：

```markdown
## 质检报告

### 总体评级：[可发布 | 带说明发布 | 需修订]

### 方法与口径复核
[问题是否答对、来源、人群、定义、对比、假设的发现]

### 发现的问题
1. [严重度：高/中/低] [问题描述 + 证据 + 对决策的影响]
2. ...

### 关键计算复核
- [指标或主张]：[已验证 / 有出入 / 未验证] — [简据]

### 图表复核
[图表或呈现问题，无则省略]

### 建议改进
1. [改进项 + 为什么重要]

### 必须告知决策方的 caveat
- [必须传达的限定]

### 未完成 blocker（与 caveat 分开列）
- [缺失访问 / 未跑检查 / 渲染坏步骤 / 待负责人确认 ...]
```

涉及 SQL、notebook、表、看板、查询 permalink 时附上路径或链接，保证复核可复现。保留原成品的来源引用，不要在质检中丢失可追溯性。

## 与其他技能协作

- 指标口径、定义、权威来源不清：调用 `retrieving-context`。
- 需要复算 SQL 明细或聚合：调用 `querying-data sql`。
- 需要复算 PowerBI 语义模型数字：调用 `querying-data powerbi`。
- 异动归因类结论的域内检查：交回 `diagnosing-anomalies`。
- 实验/效果评估类结论的域内检查：交回 `evaluating-impact`。
- 预测/目标类结论的域内检查：交回 `predicting_trends`。
- 图表诚实性需重画核对：调用 `visualizing-data`。
- 修订后需要重新落地报告：调用 `building-reports`。

## 边界

- 本技能不替你从头做分析，只验收已有成品。
- 不机械跑全部检查，按成品类型和决策风险选检查项。
- 不能验证的主张必须明示“未验证 + 需要什么才能验证”，不要假装查过。
- 质检不能替代各分析域的内部自检；域内方法论问题交回对应 skill。
- 没有源数据访问时，只能做口径/逻辑/合理性层面的审查，并在评级里说明受限。
