# 目标制定

目标是业务决策，不是纯预测。预测回答"假设不变，可能发生什么"；目标表达"团队承诺或挑战什么"。预测值只是目标制定的基准之一，还要叠加业务意愿、资源和风险。

## 基准选择

制定目标前先建立多个基准互相印证，避免单一锚点：

| 基准 | 做法 | 适用 |
| --- | --- | --- |
| 同比 | 去年同期 × 增长预期 | 有明显季节性、年度规划场景 |
| 环比 | 近几期均值/增速延续 | 趋势平稳的短期目标 |
| 趋势外推 | `forecast`（`holt_linear`/`linear_trend`/`log_linear_trend`） | 历史充足且无结构断点 |
| 自下而上 | 分渠道/分群/单量×客单等逐层加总 | 有明确业务抓手、新业务或分群差异大 |

## forecast 输出 → 目标档位

`forecast` 返回的点值与区间直接映射默认三档：

| 档位 | 锚点 | 含义 |
| --- | --- | --- |
| 保守目标 | `lower`（区间下界）或近期 run rate | 当前执行下较稳达成，置信度高 |
| 基准目标 | `value`（点预测） | 当前条件延续的正常预期 |
| 挑战目标 | `upper`（区间上界），或点值叠加增长假设/计划增量 | 需明确增长抓手或额外资源 |

注意：

- 置信度为 low（warnings 非空或 mape >20%）时，三档都要打折表述，不要把区间当 KPI 承诺。
- 挑战目标不能只给数字——必须说明所需抓手（投放、供给、人力、转化优化）及其量级。
- horizon 加长时不确定性增大，长周期目标宁可用场景（保守/中性/激进三场景）而非单条外推。

## 目标达成判断

针对"月底/季末能不能完成目标"：

1. `forecast` 传 `target` 入参，直接得到 `summary.target_gap`（预测合计 − 目标）。
2. 自行计算剩余口径：剩余目标缺口、剩余周期数、**所需 run rate**（缺口 ÷ 剩余周期）、历史平均 run rate、预测 run rate。
3. 对比所需 run rate 与预测 run rate，给出明确状态：
   - 大概率可达成（缺口小或所需 run rate ≤ 历史水平）。
   - 有风险，但仍可追回（需指出差距与候选动作）。
   - 若无额外抓手，较难达成（所需 run rate 显著超历史峰值）。
   - 数据不完整或目标口径不清，暂无法判断。

## 推荐目标时综合考虑

- **可控性**：团队在目标窗口内能否实际影响该指标。
- **提前量**：距周期结束是否还有时间改变结果。
- **波动性**：预测区间是否足够窄，能支撑承诺（区间宽 → 保守档更合理）。
- **业务意愿**：管理层要确定性、适度挑战还是激进增长。
- **资源约束**：产能、预算、供给、人力是否支持挑战档。

## 不要这样做

- 不解释风险就把目标直接设成预测值（点预测不是承诺）。
- 没有业务抓手就推荐挑战目标。
- 把低置信度预测包装成精确 KPI。
- 忽略产能/预算/供给/人力等硬约束。
- 预测结论和目标建议混在一起说——分开表达"预计是多少"和"建议定多少"。
