# validating-analyses（分析质检）

对「已经做出来的分析」做独立复核，不是从头做分析。回答一个问题：**这份成品能不能拿去给决策方看？** 重点抓产出方自己不易发现的系统性错误——口径漂移、数字不可复算、统计陷阱、图表误导——而不是重跑一遍归因或评估。横向适用：自己刚产出的、同事交接的、报告草稿、第三方结论。定位是交付链的最后一道兜底关（orchestrating-analytics 串联顺序的末位）。

## 质检用的工具

本技能 owns 无工具，纯方法论；复算与核对借用其他技能的工具（契约见各自 SKILL.md）：

| 工具 | 质检中的用途 |
|---|---|
| `retrieve_search` | 拿受治理指标定义，核对结论口径是否与权威定义一致 |
| `sql_query` | 独立重算关键数字（换写法验证，不是重跑原 SQL） |
| `report_html_get` | 取已发布报告的最终渲染态，核对图文一致 |

各分析域的内部检查不复刻：异动归因查 diagnosing-anomalies、效果评估查 evaluating-impact、预测查 predicting-trends 的域内纪律。

## 决策流程（交付前五查）

按对决策的影响排优先级，不机械全查；每查给可执行动作：

1. **口径一致**：结论里的指标定义（文字怎么写的）、`retrieve_search` 返回的受治理定义、取数 SQL 实际的过滤与聚合——三者对得上吗？重点：同名不同义、人群/排除项静默不一致、分母定义漂移、对比期是否同口径。对不上先对齐口径，不要在错误口径上继续验。

2. **可复算**：抽 1-2 个影响最大的关键数字，用 `sql_query` **换一种写法独立重算**（如原 SQL 用 join，复核时用子查询/单独聚合再对总），不是重跑原 SQL——原 SQL 错了重跑还是错。分域核对：
   - 归因类：核对 contribute 输出的 checks（residual 占比、warnings），残差大说明归因不完备。
   - 预测类：核对 backtest 指标（mape）与 confidence 是否支撑结论表述，低置信不得写成确定性判断。
   - 评估类：核对显著性前提——AB 有无 SRM（各组样本比与设计不符则结果作废）、DID 有无平行趋势检验（证据与前提见 evaluating-impact 技能）。

3. **陷阱排查**：辛普森悖论（分组结论与总体方向一致吗？分组都涨总体跌是最经典翻车）、幸存者偏差（数据集里少了谁——已流失/已删除的实体）、基数效应（小基数增长率虚高，3→9 是 +200%）、同期不可比（节假日/大促/口径变更点两侧直接环比）。join 类重点：join 前后行数、COUNT DISTINCT 主实体、多对多放大。

4. **图表诚实**：轴是否截断误导（柱状图不从 0 起、对比图刻度不一致）、比例是否夸张（Y 轴压缩放大波动）、标签与数据一致（图上数字与正文数字对得上，对照 chart spec）；报告结论与图表展示互相支持——正文说涨、图显示跌是最严重的翻车。用 `report_html_get` 查最终渲染态：图有没有坏、表有没有缺、文字有没有被裁。

5. **置信度评级**：给整体评级——高（关键数字已复算、无硬伤）/ 中（方向可信但有未验证项，须带 caveat）/ 低（存在实质性错误或方法问题）。**低置信结论必须显式标注**"未验证/低置信 + 为什么"，不得含糊交付。

## 输出要求

质检结果**附在交付物之后**，结构：通过项（查了什么、怎么验的）/ 未通过项（问题 + 证据 + 对决策的影响，按严重度排序）/ 建议（改什么、去哪改）。只回复"已完成"不算质检交付。复算用过的 SQL 要留痕，保证复核可复现。

## 陷阱与注意

- **独立视角**：假装没看过之前的推导——产出方的惯性是"验证自己是对的"，质检的价值恰恰在换视角找茬。结论意外、过于完美、与既有认知冲突的成品加倍审查。
- **时间预算**：按交付重要性分配复算深度——日常播报轻查（口径 + 图表 + 抽 1 个数字），复盘报告/对外汇报全查（五查跑满 + 关键数字全复算）。高风险对象不惜成本，低风险对象不为修辞小瑕疵阻断交付。
- **发现问题回对应技能修**：口径错回 retrieving-context/querying-data、归因错回 diagnosing-anomalies、图误导回 visualizing-data——**不要在质检环节就地改数**，质检只产出"问题 + 证据 + 建议"，修完重走质检。
- 区分 blocker（硬伤，必须改才能发）与 caveat（可带说明发布），不要混列。
- 不能验证的主张明示"未验证 + 需要什么才能验证"，不要假装查过；没有源数据访问时只能做口径/逻辑层面审查，评级里说明受限。
